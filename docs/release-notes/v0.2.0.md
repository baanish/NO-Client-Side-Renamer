# v0.2.0: shared CSV rosters

Configure up to eight HTTPS CSV endpoints and the mod fetches every enabled roster automatically on load. Each source has its own optional token in the `PASSWORD` request header. Local aliases take priority, followed by the lowest-numbered loaded roster for that SteamID.

Each CSV requires `PlayerName` and `SteamID` columns. Downloads run independently in the background and stay in memory. The mod validates each whole roster before applying it and retains that source's previous valid roster if a refresh fails. Editing or disabling one source clears only its aliases and cancels its outdated request. The original `Remote CSV` settings remain roster 1; additional sources use `Remote CSV 2` through `Remote CSV 8`.

Requests reject redirects and invalid HTTPS certificates, including when another mod installs a permissive global certificate callback. CSV body size, time, row and name limits bound roster loading. The installed Mono handler does not enforce the requested response-header limit. The parser rejects invalid or duplicate IDs, markup and control characters. Downloaded content is never executed or written into local alias files.

The token field is masked in F1 but stored as plain text in BepInEx config. Use a dedicated roster token and keep that config private. See the [setup guide](../USER_GUIDE.md#fetch-a-shared-csv-roster).

The Release build and 141 automated tests pass, including the production certificate policy, a real .NET TLS handshake against an untrusted certificate, transport cleanup, multiple-roster priority and failure isolation. NuGet vulnerability metadata could not be refreshed. This is an unreleased test build. Startup HTTP behavior, Mono TLS isolation and cache refresh need in-game verification. Vanilla-peer isolation remains unproven in both join directions.
